### B18 — Agreed high-level plan

**Entry and presentation.** Opening a connection opens Browse mode without asking for a second connection. Show connection and language selectors, the existing ID/path/name input, and one full-width tree. Retain icons, indentation, lazy expansion, loading/error feedback, selection and refresh behavior. Omit the second column, difference indicators, swap, language lock and directional transfer controls in Browse mode. Existing explicit comparison entry points should still open Compare mode.

**Single-connection actions.** Support expand/collapse, refresh and cancellation; ID/path lookup and indexed name search on the selected connection; sites and favorites; copying IDs/paths; item details; and public-page navigation for eligible items. Publishing is a first-class Browse workflow: retain Standard, Traced and Power Publish, together with matching item task plug-ins. Preserve the existing Operations queue, history, confirmation and Workspace Trust behavior. Cross-connection diff and transfer actions belong in Compare mode.

**Item Details.** In Browse mode, the bottom pane presents one item's metadata and field values, rather than a paired field comparison. Retain field visibility controls and shared/unversioned markers. Show ID, path, template, language and version, plus Open public page when available. The initial scope is read-only field inspection; direct field editing is not included. Explicit publishing and task actions remain available.

**Browse to Compare.** Put the browsed connection on the left and reuse its last comparison partner when available. Remember this relationship per browsed connection across reloads, using saved connection identities rather than secrets. Restore the partner language as well, validating that the saved connection and language remain available. Keep the partner changeable. If no partner is remembered or the remembered connection was deleted, prompt the user to select one; do not choose an arbitrary connection. Cancelling leaves Browse intact. If a saved language is unavailable, request a valid selection rather than silently changing the comparison.

**Same-connection comparison.** Allow the same connection on both sides with independently selected languages, for example English versus German. Keep language locking explicit in Compare mode and do not silently apply it in a way that overwrites a restored cross-language comparison.

**Compare to Browse and state.** Always retain the left comparison side without a selector or prompt. Preserve its connection, language, root and selected item. Preserve expansion and scroll state where practical, and keep mode-specific navigation state so switching does not unnecessarily restart browsing. New navigation or mode changes must supersede pending loads and prevent stale results from replacing the current view.

**Implementation acceptance.** Verify opening with one configured connection; search and details in Browse; publishing and task availability; absence of diff/transfer controls; first-time partner selection and cancellation; remembered partner/language after reload; deleted partners and unavailable languages; same-connection cross-language comparison; explicit language-lock behavior; and state restoration during cancelled or superseded loading. Use domain tests and extension-host checks where appropriate, plus focused manual checks for tree layout, keyboard access and mode transitions. Subtasks #1–#4 are delivered; full integrated acceptance remains in #5.

- [ ] **B24 — Component/item editor: first development step.** Build an editor screen for ordinary items and component datasource items, with locale selection. Exclude file/image/media editing, Media and Complex Field Types, and Developer and System Field Types for now. - [ ] **B25 — Persist component-editor changes on Save.** Save edited field values through the existing Authoring mutation/client mechanisms, analogous to syncing a specific field value in the diff view. Validate values and persist them for the intended item, language and version, respecting shared/unversioned field scope. Plan stale-value/conflict handling, failure feedback, unsaved-change behavior and post-save refresh. Save must not create a new language version. When editing fallback content, persist to its existing effective source locale/version, with the impact warning described in B26; do not materialize fallback values in the requested locale. Verify the exact mutation flow before implementation.
- [ ] **B26 — Editor locale selection and visible fallback chains.** Permit selecting any configured environment locale, including one with no local version of the item. Resolve fallback using the environment's applicable rules and visibly distinguish the requested locale from the effective source. Display the full chain, for example `fallback: en-us -> en` or `fallback: en-nz -> en-au -> en` when intermediate versions are missing. Handle item-level and field-level fallback without hiding their provenance, and show when no usable fallback exists. Decided: Save edits the existing fallback source and never creates a new language version. Before saving a page/item through fallback, warn that changing the source can influence other pages and locales using it, show the requested-to-source chain and actual write locale, and allow cancellation. Where reliably determinable, list affected locales, including transitive fallback chains; distinguish confirmed or potentially affected locales and state when impact information is incomplete. Do not claim that no other pages/locales are affected merely because references or fallback consumers could not be fully discovered. Respect field-level source provenance when fields resolve from different locales; expose their write targets rather than assuming one source for the entire item. Coordinate with B03/B04 while keeping editor behavior separate from stored-state comparison.
- [ ] **B27 — Page editor: read-only component and reference tree.** For a page, initially present its effective rendered controls/components as a read-only tree derived from applicable shared and final presentation. Resolve the effective layout rather than assuming that simply concatenating shared and final definitions reproduces the page. Include nested datasource references, such as items selected in a datasource's Treelist, and recursively follow further supported item references until no further references remain. Define reference field coverage and distinguish rendering placement from datasource-reference relationships. Follow the selected locale and fallback behavior as the live page would; verify the observable limits instead of claiming to reconstruct arbitrary application logic. Rebuild the tree when locale changes because renderings, datasources and referenced values can differ. Each item node shows its name and effective locale, with fallback visibly identified. Handle cycles, missing references, cancellation and large graphs explicitly without silently presenting a truncated tree as complete.
- [ ] **B28 — Editor entry points and locale-aware navigation.** Add an Edit action to the diff-tree item context menu, targeting the clicked connection/side and opening the page editor for a page or component/item editor for an ordinary item. Double-clicking an editable item in the page component/reference tree opens its component editor in the appropriate language, preserving requested/effective locale and fallback context. Use the existing effective source locale as the fallback edit target, retaining the requested locale and chain for the B26 save warning; handle unsaved changes during navigation. Reuse verified page identification where applicable.
- [ ] **B29 — Publish directly from page and component/item editors.** Allow the currently opened page or item to be published from its edit screen using all three existing modes: Standard Publish, Traced Publish and Power Publish. Proposed UI: a Publish menu in each editor toolbar with one action per mode, reusing the existing configuration, scope review, Operations queue and evidence views. Carry the editor's connection, item/page identity and locale context into publishing and keep the actual target visible. For an ordinary item, do not silently replace the publishing target with its owning page; keep route/application verification context separate from the publish target. Preserve both requested and effective source locale for fallback content and explicitly resolve the publication language/scope; saving the fallback source does not automatically imply publishing all dependent locales. Define how saved changes feed publishing scope and verification, including the remaining Power Publish work in B23. Unsaved edits must not be represented as published: proposed behavior is to offer Save and publish, Publish saved version, or Cancel, with the B26 fallback-impact warning applied before any save and publishing blocked if that save fails. Save alone must not implicitly publish. Exact menu wording, fallback publication defaults and handoff details remain to be designed. Initial delivery starts with B24 and item persistence/locale support, followed by the read-only page tree and navigation; publishing remains available from that read-only page view, while full page-layout editing stays outside the initial scope.

These editor TODOs extend beyond B18's initial read-only Browse details pane. They do not retroactively add direct editing to the Browse-mode delivery plan. Fallback Save targets the existing source without creating versions, as decided in B25/B26. Exact field support, impact-discovery coverage, effective presentation resolution and publishing handoff details still need technical planning before their dependent implementation work.
