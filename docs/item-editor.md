# Edit ordinary items

[Documentation index](README.md) · [Project overview](../README.md)

Right-click an ordinary content or component datasource item in **Browse**, or on its specific side in **Compare**, and choose **Edit…**. The editor opens in the main editor area; Item Details remains a read-only inspector. Tabs are pinned to the connection, item, locale and concrete numbered version. Reopening the same target reveals its draft. Tree navigation does not retarget the tab. **Open existing locale/version…** opens another tab without creating versions.

## Field support

| Field type | Editing support |
| --- | --- |
| Single-Line Text, Multi-Line Text | Read/write; preserve whitespace and newline conventions. |
| Checkbox | Read/write; checked or unchecked, with no Clear button. |
| Integer, Number | Read/write with string validation; no rounding. |
| Date, Datetime | Read/write for supported representations; ambiguous existing formats stay read-only. |
| Droplist, Grouped Droplist | Read/write names with supported Sources. |
| Droplink, Grouped Droplink, Droptree | Read/write one item ID with supported Sources. |
| Checklist, Multilist, Treelist, TreelistEx | Read/write ID lists with supported Sources; Checklist has no reorder controls. |
| Name Value List | Read/write valid encoded rows. |
| General Link | Read/write supported ordinary links; custom/DAM destinations stay protected. |
| Image, File | Read-only metadata and on-demand supported previews. |
| Rich Text | Read-only sandboxed preview and original HTML. |
| Other or unsupported field representations | Read-only; the reason remains visible. |

Eligibility also depends on an existing exact-locale version, valid metadata and the editor's page/system/fallback protections. A supported type alone does not make every field writable.

## Basic values and clearing

Basic editable fields are Single-Line Text, Multi-Line Text, Checkbox, Integer, Number, Date and Datetime, grouped by template section with type, scope and value-source metadata. Text whitespace and existing newline conventions are preserved; numeric strings are validated without rounding. **Clear** stores an explicit empty value, never a reset to inheritance. Checkboxes are checked or unchecked directly and have no Clear button. Untouched fields, including inherited and Standard Values, are not written. Editing those values creates an explicit override.

Datetime controls display **UTC**, with no browser-local conversion, and write Sitecore's compact `yyyyMMddTHHmmssZ` format. Date controls use date-only input and midnight storage. Untouched representations remain unchanged. Legacy Datetime values without a UTC suffix, non-midnight Date values and unrecognized formats stay read-only rather than guessing their meaning. See [Sitecore's documented field serialization](https://doc.sitecore.com/sai/en/developers/sitecoreai/introduction-to-framework-agnostic-sitecore-development/content-rendering/field-types-in-rendering-data.html).

## Save, conflicts and recovery

**Save** (also Ctrl+S) requires native confirmation before contacting Sitecore, including when autosave invokes it. The warning explains shared/unversioned impact and explicit overrides. The editor checks identity, numbered version, template and changed-field values/metadata again before writing, then reads back the same version. This is not an atomic compare-and-set: concurrent server edits can still occur between requests. No mutation is retried automatically. An uncertain or partial save preserves the draft and exposes **Check save outcome**; unresolved outcomes block further writes. Save failures identify the operation stage and safe error details; raw server responses are omitted. **Revert** reloads the pinned version and discards the draft, not the remote write.

VS Code custom-document dirty tabs, close/save/discard prompts and backups protect drafts. Content snapshots and save journals are stored locally in the extension's global storage, with dirty backups managed by VS Code; they contain item content, not credentials. Draft edits participate in VS Code Undo/Redo; each completed reorder is one edit. Undo after Save changes the draft only and needs another confirmed Save to affect Sitecore. Revert reloads content and ends the previous draft history; backups preserve draft values, not the full undo history. Rich Text and media remain read-only; system fields and page presentation editing are unsupported. Missing exact-locale versions and fallback-derived fields are read-only; choosing another existing locale is explicit, never an inferred fallback write. Page-tree editing and publishing from the editor are not available; use [tree publishing](publishing.md).

## Field labels, groups and information

Every item-editor field, including read-only fields, has a hover/click/focus information icon containing its internal name, type, scope, value source and stored value. Reference paths appear there when resolved. Stored values describe the loaded snapshot until Save or reload; drafts remain in the controls. Long values scroll within the popover. Read-only reasons remain visible beside the field.

Item-editor fields are grouped into collapsible Sitecore template sections, ordering sections by section sort order and then name, and fields within them by field sort order and then name. Content groups start expanded; groups containing only standard-template fields start collapsed. Click a heading or use Enter/Space to toggle it. Each editor remembers section expansion across refreshes and webview restoration. Collapsing does not discard drafts. Inherited sections with the same name share one visual group, using the lowest contributing section sort order. Fields are sorted across the merged group. Previous expansion settings migrate by keeping the merged group open if any contributing group was open.

Editor field headings resolve template-field Title metadata asynchronously (selected locale, then English for presentation only), falling back to the internal field name. Authoring value labels such as “standard value” are never used as headings. Internal names and value provenance remain in the information box.

## Single-selection fields

Droplist and Grouped Droplist store the selected item's **name**. Droplink, Grouped Droplink and Droptree store one item **ID**. Click the selection textbox (or press Enter, Space or Arrow Down) to open searchable flat/grouped choices or a tree with explicit child-level navigation. Search filters the current level; it does not search unloaded descendants. Choosing a value closes the picker; Escape, clicking outside or leaving the field also dismisses it. **Clear** sits to the right of the textbox. Names and paths identify choices. Selected Droplink, Grouped Droplink and Droptree references resolve automatically in the background when fields appear, including read-only fields; the textbox shows only the item name. Hover, focus or click the information icon to see field metadata, the stored value and the full item path. Missing/inaccessible references show “Unavailable item.” Name-storing Droplists display their stored name immediately. Choice lists still load only on request. Loading, filtering or editing another field never clears or rewrites an unresolved/out-of-source value. Only an explicit selection or **Clear** changes it. Duplicate names in name-storing lists are disabled because they cannot uniquely identify an item.

Supported Sources are an absolute `/sitecore/...` root path or a root item GUID. Flat lists offer direct children, grouped lists offer grandchildren, and Droptree offers descendants (not the root itself), following [Sitecore's selection-source rules](https://doc.sitecore.com/xp/en/developers/92/sitecore-experience-manager/controlling-the-list-of-items-in-a-selection-field.html) and [field value representations](https://doc.sitecore.com/sai/en/developers/sitecoreai/introduction-to-framework-agnostic-sitecore-development/content-rendering/field-types-in-rendering-data.html). The [bounded child queries](#bounded-child-query-sources) are also supported for flat lists. Empty Sources, other queries, relative paths, SXA tokens and parameter/filter expressions remain read-only. No unsupported expression falls back to unrestricted browsing or a tree crawl.

Source and Type are read from the template field item. If it has no version in the editor locale, an advertised existing version supplies only verified **shared** metadata; content choices and writes retain the editor locale. Missing/inaccessible metadata keeps that field read-only. Limits are 64 field definitions per item, 1,000 choices per list or expanded branch, 50 groups, 20 child pages and a 30-second request timeout. Incomplete/over-limit lists are rejected, not offered as partial selections. Save rechecks field Source and allowed membership; moving, deleting or renaming a selected item can therefore block Save. These checks do not claim an atomic lock against concurrent server changes. Existing fallback/system/page restrictions still apply.

## Multiple-selection fields

Checklist, Multilist, Treelist and TreelistEx use the same editor draft and Save/Revert workflow. **Add items…** opens a compact searchable popover for Checklist/Multilist, or a lazy tree with child-level navigation for Treelist/TreelistEx. Click an available row (or use Arrow keys and Enter) to add it immediately to the draft. The popover stays open; selected rows show **✓ Added** and cannot add duplicates. Remove and reorder selections only in the selected list outside the picker. Selected items stay visible separately, including unavailable references. Drag the left handle to reorder Multilist and tree-list selections within the same field, or focus it and press **Alt+Up / Alt+Down**. An insertion line marks the drop position, long lists scroll near their edges, and Escape cancels dragging. Each move retains focus and announces its new position. The compact **×** action on the right removes a selection; full names and paths are available in tooltips. Cross-field, other-editor and external drops are rejected. Checklist preserves retained order and has no reorder controls. **Clear** explicitly empties the field.

Supported Sources are absolute Sitecore root paths and item GUIDs. Checklist/Multilist offer direct children; Treelist/TreelistEx offer descendants, excluding the root. The [bounded child queries](#bounded-child-query-sources) are also supported for Checklist/Multilist. Other queries, empty/relative Sources, SXA tokens and parameterized Sources (including DataSource and template/display filters) remain read-only, never broadened into unrestricted browsing. See [Sitecore selection-source semantics](https://doc.sitecore.com/xp/en/developers/104/sitecore-experience-manager/the-template-field-template.html).

[Values are pipe-separated item IDs](https://doc.sitecore.com/sai/en/developers/sitecoreai/content-modeling-and-presentation/data-templates/data-template-fields/the-data-template-field-types/the-simple-field-types.html). Retained IDs preserve their original representation and order; newly selected IDs use braced GUIDs. Unknown or out-of-source references remain until explicitly removed, including when adding/reordering valid choices. Duplicate IDs, malformed lists and lists over 256 selections remain read-only. Loading, filtering, incomplete pages and failures never clear selections. Limits remain 1,000 choices per list/branch, 20 pages, 64 Source definitions per editor and 30-second request/validation windows. Complete branches load on demand; partial results are not offered.

Save rereads the pinned exact-locale version and Source metadata, rejects value/type/Source drift, and validates **newly added** IDs against current membership. Retained unavailable references may remain or be explicitly removed. No content version is created; fallback-derived, page and system fields remain protected. The existing non-retried mutation, journal and readback rules apply.

## Structured fields

### Name Value List

**Name Value List** has compact name/value rows with Add row, Remove and Clear. Values use URL-parameter encoding: `&` separates entries, the first `=` separates name/value, percent escapes decode as UTF-8 and `+` represents space. Edits encode reserved characters and Unicode; unchanged row halves retain their exact original encoding. Empty values are supported. Existing duplicate entries remain separate and are never combined; new duplicate keys (including case variants) are rejected. Empty keys, missing separators, malformed escapes, control characters and lists over 256 entries remain read-only. Removing all rows or Clear stores an explicit empty string, not a reset to Standard Values. No row reordering is offered.

### General Link

**General Link** supports ordinary internal, external HTTP(S), email and anchor links. The form exposes applicable destination, text, title, target, CSS class, anchor and internal query-string properties. Internal destinations use the existing bounded tree picker on the editor's pinned connection/locale. A verified empty Source browses `/sitecore/content`; explicit absolute Source paths/IDs restrict the tree. The current Source item can also be chosen. New destinations are resolved and checked against fresh Source metadata before Save; retained unresolved IDs survive unrelated edits. Unsupported or unavailable Sources disable editing.

The General Link control uses Sitecore item / External URL / Email / Anchor radio buttons, one destination control and an inline properties chevron. Expanded properties are inset with surrounding spacing to group them within the field. Destination focus/click, type changes or the chevron are intended to expand properties (see the [known B31 issue](troubleshooting.md#general-link-properties-b31)); moving between inputs never collapses them. A collapsed summary shows non-default text/title/target/class/anchor/query properties. Validation errors keep properties expanded. Arrow keys, Home/End and Space/Enter operate the type buttons. Internal destinations display the Sitecore path and retain the existing Source-aware picker.

Type switching keeps common text/title/target/class values and remembers each type's destination, anchor and query draft. Incomplete inactive alternatives are allowed and survive native Undo/Redo, backup and reload; only the active valid link can be saved. Conversion removes attributes that no longer apply to the selected type. Successful Save (including a no-content-change Save), explicit Clear and Revert discard temporary alternatives; Undo can restore the previous local draft after Save, while Revert ends that history. Neither switching nor collapsing saves content automatically. Custom/DAM metadata exposes only the current protected type; unsupported link kinds show their type and stay read-only.

Unchanged General Link XML is preserved exactly. Changes patch only edited ordinary attributes, preserving other attributes, quoting and spacing. Custom attributes (including DAM mappings) restrict edits to link text, title, target and CSS class; their destination and kind stay read-only. Clear is explicit. Native Undo after Save/Clear retains the original XML and encoded rows, but saving the restored draft requires confirmation again. New anchor links use the documented `url` attribute; existing anchor-only or matching URL/anchor representations are preserved. Conflicting destinations remain read-only. There is no executable link preview. Media/JavaScript/custom link kinds, General Link with Search, XML with namespaces/child nodes/DTDs, malformed XML, unsafe URLs and unsupported email header/query variants remain read-only. Asset selection, uploads and media editing are not included.

Both types use the existing exact-locale, fallback protection, shared-scope warnings, dirty draft/backup, conflict detection, non-retried writes and readback workflow. Invalid edits remain visible drafts with validation feedback. Consuming application behavior for duplicate keys is not inferred.

## Item pickers

Single- and multi-selection pickers share a bounded popover anchored to their field control, normally below it and above when needed to fit the viewport. Search stays fixed while results scroll. Names are prominent; a muted relative parent path appears only to disambiguate duplicate labels, with internal names also shown when duplicate labels share a parent. Full item paths are in tooltips. The picker header shows only the final item name, with the complete Source/path/expression in its tooltip; this presentation never changes selection scope.

Escape, outside click or the close button dismisses the popover; additions already made remain in the draft. Focus returns to the trigger on Escape/Close, while clicking another control respects that destination. Arrow keys navigate result actions and Enter chooses/adds. Single-selection closes after choosing; multiple-selection keeps focus and shows Added state. The tree's child arrow opens that item's children and Back returns to the parent; filtering applies only to the displayed level. Loading/errors and empty/all-added states are explicit, with no partial page results or hidden tree crawl. Save, Source validation, Undo/Redo and backup behavior are unchanged.

## Bounded child-query Sources

Droplist, Droplink, Checklist and Multilist additionally accept exactly `query:./child::*[@@templateid='GUID']` or `query:./*[@@templateid='GUID']`. Whitespace between tokens, paired single/double quotes, and uppercase/lowercase GUIDs in compact, dashed or braced-dashed form are accepted. Keywords remain case-sensitive. The query starts at the pinned **edited item** in its connection and locale. Only immediate children whose direct template ID equals the filter are offered; descendants and template inheritance are not included. Returned order is preserved.

This is bounded local evaluation over complete Authoring child pages, not a general Sitecore query evaluator or indexed-search approximation. The [documented Authoring operations](https://doc.sitecore.com/xp/en/developers/104/sitecore-experience-manager/query-examples-for-authoring-operations.html) do not establish a context-bound field-Source evaluator. All children count toward the existing 1,000-item/20-page limit before filtering; missing template metadata or incomplete pages fail closed. Grouped/tree query Sources, unions, ancestor/descendant axes, extra predicates, operators and parameterized Sources remain read-only. Save rechecks Source and fresh membership for additions; retained outside-source IDs remain intact. No Sitecore Source configuration needs changing.

## Read-only fields and previews

Read-only fields remain inspectable. The item editor shows Image and File XML attributes (including unknown/custom mappings), available alt text, dimensions and references. A valid media ID identifies a Media Library reference; DAM identifiers identify Content Hub. Ambiguous or unknown providers are labeled accordingly. Empty strings, unreadable values, malformed populated values and preview failures are distinct. Raw stored values are escaped, inspectable and never rewritten by this presentation. Existing locale/version/scope/fallback labels and field-visibility controls are retained.

Use **Load preview** for an Image with a stored supported URL, **Check file reference** for a File, or **Resolve media reference** for a Media Library ID without a supported URL. Resolution uses the captured connection/locale and verifies the returned ID and Media Library path. It does not invent a media URL. Asset requests start only on demand, with at most three concurrent requests per document and a 20-second timeout. Asset HTTP reads have no retries; Media Library item resolution uses the existing Authoring read policy. Raster previews support PNG, JPEG, GIF and WebP with verified MIME/signatures, capped at 8 MiB; SVG previews rebuild a bounded shape-only document (1 MiB, 10,000 tags, 64 nesting levels), with paths, groups, basic shapes and local clipping. Scripts, styles, external references, embedded images, animation, text and unsupported markup are rejected. The rebuilt SVG is used only as an image data URI; original SVG is never injected into the DOM. Other formats retain metadata/source. An explicit **Open asset** action appears only after a successful supported response. File validation uses HEAD and supports PDF, ZIP, binary, text, raster image, MP4 and MP3 responses. Redirects, private/unavailable assets, unexpected formats and oversized responses leave metadata/raw content intact with a failure message and retry option.

Only explicit same-origin `/-/media/` or `/~/media/` URLs receive existing Sitecore authentication. Content Hub `/api/public/content/` URLs on `*.stylelabs.cloud`, `*.stylelabs.com`, `*.stylelabs.io` and `*.sitecorecontenthub.cloud` are fetched anonymously. Gateway/private URLs, custom CDN hosts, credentials/signature/token query parameters and unsafe schemes are not fetched. No credentials reach the webview or an external host. Remote URLs are never webview image sources: only bounded raster data or rebuilt shape-only SVG is passed to the editor. TLS verification remains enabled; environments with enterprise certificates must have a trust configuration accepted by the extension host. No Content Hub credential setup is added.

Rich Text uses a read-only sandboxed iframe with an opaque origin and no sandbox permissions. Inline formatting and embedded CSS are retained inside that document; scripts, event handlers, navigation, forms and embedded active content are removed. A restrictive frame CSP blocks all external requests, including CSS imports, fonts and background images. Styles are placed in nonce-authorized stylesheets; the outer webview does not permit arbitrary inline styles. Embedded images become alt-text placeholders. The preview has a resizable, scrollable viewport and a neutral white background; it does not load website stylesheets. HTML size/depth/node limits do not truncate the escaped **HTML source (unchanged)**. This adds no editing or Sitecore mutations. The same preview is used in Item Details; iframe content clicks do not trigger the surrounding text-diff action.

Item Details uses the same Image/File metadata, raw-value and Rich Text display; asset loading/resolution remains in the item editor. Text diff and field transfer semantics remain unchanged.

References: [Sitecore image fields](https://doc.sitecore.com/xp/en/developers/92/sitecore-experience-manager/access-image-fields.html), [Content Hub attribute mappings](https://doc.sitecore.com/xp/en/developers/connect-for-ch/51/connect-for-content-hub/change-the-image-tag-attribute-mapping-in-sitecore.html), [Content Hub public links](https://doc.sitecore.com/ch/en/developers/cloud-dev/public-links.html).

Image/File attributes and original XML are kept in the editor’s existing information box. The main field shows a short read-only label, preview controls and the preview/result. A white preview backdrop keeps dark logos visible across themes. TLS certificate failures and unsupported SVG markup receive distinct, redacted messages.
